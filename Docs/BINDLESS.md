# Bindless contract for MIRA, FACET and UVRT

## Ownership and current public API

OpenRHI owns native heaps, descriptor encoding, limits, Validation and shader ABI. MIRA owns a shared device-lifetime resource/sampler registry and its allocator, generations, publication, recording leases and retirement. FACET and UVRT consume typed indices in GPU scene/material/geometry records through the shared registry. UVRT owns scene lighting. GPU work selects descriptors from those records; a fixed descriptor-set binding renamed as a heap does not satisfy this migration.

Include `OpenRHI.h`, then `Extensions/OpenRHIDescriptorHeap.h`. Query `DescriptorHeapInterface` with `openrhiGetInterface`. Its existing public operations are:

- `CreateDescriptorHeap(device,{resourceCapacity,samplerCapacity},heap)` and `DestroyDescriptorHeap`.
- `WriteResourceDescriptors(heap,writes,count)` copies resource views into arbitrary resource slots. `WriteSamplerDescriptors` copies sampler descriptors into a separate index namespace.
- `CmdSetDescriptorHeap(command,heap)` binds the heaps. Resource creation, view creation, shader type, resource barriers, queue submission and lifetime remain explicit public CoreInterface responsibilities.

These operations use raw slots. MIRA implements allocation/free, typed handles and generations above this boundary; the RHI performs no slot allocation, generation checking, automatic retirement or resource transition on a heap write. Shader-visible descriptors must be initialized before their first possible access, including dynamically selected branches.

## Runtime admission and limits

Read `CoreInterface::GetDeviceDesc` after creation and retain the exact adapter/driver/backend identity with the admission result. Check both the interface result and `features.descriptorHeap`; check each requested capacity against `descriptorHeap.resourceMaxNum` and `samplerMaxNum`, and each root payload against `rootConstantMaxSize`, `rootDescriptorMaxNum` and `rootSamplerMaxNum`. Zero capacity omits that heap; at least one capacity must be nonzero. Admission failure returns a concrete unsupported/limit/allocation result before publishing indices. Capacity is fixed for an admitted heap epoch. Deduplicate sampler states within the admitted sampler budget.

| Backend | Supported transport in the current implementation | Admission and qualification |
|---|---|---|
| Windows D3D12 | Native shader-visible CBV/SRV/UAV and sampler heaps; SM 6.6 direct indexing | `features.descriptorHeap`, `tiers.bindless>=2`, SM>=606 and appropriate limits. Implementation enables this for native resource binding tier 3 plus SM 6.6. Query current limits rather than allocating the maximum |
| Native Metal 4 | Resource/sampler argument-buffer storage through the same public heap interface | Apple platform baseline, interface and queried limits. Native tables contain 24-byte entries; sampler capacity is bounded by native device capacity and the backend's family limit. Source implementation and ABI are audited; Apple runtime qualification remains required |
| Vulkan with EXT heap | `VK_EXT_descriptor_heap`, shader untyped pointers and buffer device addresses | `features.descriptorHeap` and queried limits; do not infer this path from Vulkan 1.3/1.4, SM number or `tiers.bindless` alone. The latter currently describes descriptor-array support and can remain 1 while native heaps are supported |
| Vulkan without EXT heap | Persistent indexed typed descriptor arrays through CoreInterface pools/sets | Use `tiers.bindless`, `tiers.resourceBinding`, `nativeCapabilities` and per-range/per-stage limits. The baseline reports runtime arrays, partially bound descriptors and sampled-image nonuniform indexing. Other nonuniform descriptor classes need explicit native feature evidence before admission; the current public capability mask does not expose every Vulkan per-type nonuniform bit |
| NONE | Automated host tests | Backend availability is distinct from GPU bindless execution |

For the Vulkan array transport, bind persistent indexed resource/sampler arrays once for the pass, with capacities, ARRAY flags and layouts matched to pinned Slang reflection. PARTIALLY_BOUND permits unused holes only where the tier supports it; every referenced slot stays valid. VARIABLE_SIZED_ARRAY and ALLOW_UPDATE_AFTER_SET each have their own documented tier/flag/limit requirements. Use mutable ranges only when `features.mutableDescriptorType` and the shader/layout requirements are satisfied. Updating after binding does not authorize overwriting GPU-visible live descriptors. A single submission/queue fallback or per-object descriptor copy is not a substitute for an indexed-array transport. Report an unavailable descriptor class explicitly until its feature evidence and native tests exist. Device-address-based buffer records are a separate explicit shader transport requiring address, bounds, ownership and native tests; `GetBufferDeviceAddress` supplies the public address.

## Shader types, indexing and binding order

The GPU payload stores separate resource and sampler indices. Each typed resource accessor must match the descriptor's resource kind, shape, view format and read/write usage. For D3D12 Slang, assign `ResourceDescriptorHeap[index]` to a typed local (`Texture2D`, `RWTexture2D`, structured/raw/typed buffer, constant buffer or acceleration structure), and assign `SamplerDescriptorHeap[index]` to `SamplerState` or `SamplerComparisonState`. Mark lane-varying indices with `NonUniformResourceIndex` for each heap. Derive ray-query/AS admission from the public ray-tracing capabilities separately.

A heap-mode PipelineLayoutDesc has zero descriptor sets and `RESOURCE_HEAP_DIRECTLY_INDEXED` and/or `SAMPLER_HEAP_DIRECTLY_INDEXED` according to its shaders. Root constants/descriptors retain their explicit layout and limits. Module shader records use a schema/version shared by host and shader; layout/reflection receipts are generated by pinned Slang 2026.20. The D3D12 qualification fixture uses rootRegisterSpace=1, an 8-byte register-b0 root payload and resource slots 7/29. Heap lookups themselves reserve no D3D register bindings. A pass with a larger scene payload declares and reflects its own root schema; modules must not independently invent conflicting meanings for shared record fields.

### Pinned nonuniform-index lowering constraint

For the pinned Slang 2026.20 DXIL sm_6_6/O3 path, keep descriptor selection in plain integer variables and apply NonUniformResourceIndex directly at each heap subscript that requires nonuniform indexing:

```slang
uint source = (lane == 0) ? input0 : input1;
uint destination = (lane == 0) ? output0 : output1;
StructuredBuffer<uint4> inputs = ResourceDescriptorHeap[NonUniformResourceIndex(source)];
RWStructuredBuffer<uint2> outputs = ResourceDescriptorHeap[NonUniformResourceIndex(destination)];
```

Caching the intrinsic's result in two uint temporaries before those lookups reproduced an index-alias hazard: emitted DXIL contained one heap handle annotated as both the structured SRV and the structured UAV, using the destination selection. Applying the intrinsic at the two subscripts preserved two distinct nonuniform heap handles. A minimal CPU-only reproduction removes the UVRT path/material algorithms and uses strides16/8; UVRT's original path fixture observed the same pattern with strides400/160 and caught the wrong reads through its UAV sentinel/readback checks. Separate HLSL-target inspection of the minimal source already shows the selected input temporary overwritten by the output selection before both heap accesses. Treat this as an observed pinned compiler constraint; exact internal compiler-pass diagnosis remains separate.

Tests/BindlessNonUniformIndex.slang compiles both source forms through the unchanged pinned CMake/OpenRHISlang.cmake helper. OpenRHI.Bindless.NonUniformCompiler disassembles them with the pinned DXC, checks the direct form's two independent nonuniform heap indices and separate SRV16/UAV8 annotations, validates root/workgroup reflection, and records the stored-result behavior. Neither diagnostic binary is dispatched. The test records compiler/downstream/source/binary/reflection/disassembly hashes under `_Build/Testing/BindlessNonUniformCompiler/`; the standalone A/B and HLSL inspection artifacts are under `_Tmp/BindlessNonUniformRepro/`. It does not require future compilers to retain the defect. Preserve direct-subscript annotations through the module migration and requalify compiler changes with these CPU checks plus independent native sentinel/readback fixtures before relaxing the rule. Existing bindless texture/sampler and buffer fixtures already use the supported expression form. Vendor compiler sources and binaries remain unchanged.

### Native binding order and target ABI

The native D3D12 order is **heap -> pipeline layout -> pipeline -> root payload -> draw/dispatch**. Bind both heaps before a directly indexed root signature that consumes both. If heap identities change, establish the corresponding pipeline layout and roots again before execution. This requirement is reproduced by native debug-layer error 1419 when reversed and is specified by [Microsoft](https://microsoft.github.io/DirectX-Specs/d3d/HLSL_SM_6_6_DynamicResources.html#setdescriptorheaps-and-setrootsignature).

Metal shader access uses OpenRHI's public `OpenRHI.slang` 24-byte entry ABI and typed table accessors. Native buffer slots are 0 for resources, 1 for samplers, 2 for the root payload. Texture handles occupy the texture-entry field; sampler handles occupy the sampler-entry field; buffer addresses and metadata use their declared fields. Preserve reflection-derived offsets, entry sizes and the native binding slots. Slang DescriptorHandle bytes and combined texture/sampler handles are target-specific; storing one target's opaque handle bytes as a portable scene handle is not supported by this contract. Metal metallib assembly and native sampled/buffer/AS execution must be qualified on Apple hardware.

For Vulkan, use the actual compiled target's reflected heap/set/binding metadata and appropriate native EXT capability compilation. The current generic SPIR-V compiler profile alone does not establish EXT-heap lowering. Indexed typed arrays use their matching reflected ranges; keep logical resource kinds and backend table indices explicit. [Slang's descriptor-handle guidance](https://github.com/shader-slang/slang/blob/master/docs/user-guide/03-convenience-features.md), [Vulkan descriptor heaps](https://docs.vulkan.org/spec/latest/chapters/descriptorheaps.html) and the public OpenRHI shader header define the respective boundaries; qualify the pinned compiler outputs, not moving documentation alone.

## Descriptor-class provenance and admission

Resource/sampler namespace separation is the first check. The host registry also stores an exact view class and creation traits. Module-owned public callbacks carry those traits without importing MIRA headers or reading native backend objects. Derive the traits in the same adapter that successfully calls the public descriptor factory, from the actual factory inputs; avoid separately retyping a tag at each call site.

| Registry class | Public creation provenance | Public DescriptorType category |
|---|---|---|
| Constant-buffer view | CoreInterface::CreateBufferView, BufferView::CONSTANT_BUFFER | CONSTANT_BUFFER |
| Typed buffer SRV / UAV | BufferView::BUFFER / STORAGE_BUFFER | BUFFER / STORAGE_BUFFER |
| Structured buffer SRV / UAV | BufferView::STRUCTURED_BUFFER / STORAGE_STRUCTURED_BUFFER | STRUCTURED_BUFFER / STORAGE_STRUCTURED_BUFFER |
| Raw buffer SRV / UAV | BufferView::BYTE_ADDRESS_BUFFER / STORAGE_BYTE_ADDRESS_BUFFER | STRUCTURED_BUFFER / STORAGE_STRUCTURED_BUFFER |
| Sampled texture | CoreInterface::CreateTextureView, TEXTURE / TEXTURE_ARRAY / TEXTURE_CUBE / TEXTURE_CUBE_ARRAY | TEXTURE |
| Storage texture | TextureView::STORAGE_TEXTURE / STORAGE_TEXTURE_ARRAY | STORAGE_TEXTURE |
| Acceleration structure | RayTracingInterface::CreateAccelerationStructureDescriptor | ACCELERATION_STRUCTURE |
| Sampler / comparison sampler | CoreInterface::CreateSampler plus SamplerDesc::compareOp | SAMPLER |

The public DescriptorType category deliberately groups raw and structured buffer views; it is insufficient to distinguish their shader accessors. Keep the exact BufferView and its format, byte offset/size and the effective structured stride (BufferViewDesc::structureStride when provided, otherwise BufferDesc::structureStride). For textures, keep TextureView, source TextureType, view format, mip/layer slice and source sample count. Use that view format to distinguish typed float/uint/sint shader access and sRGB interpretation; source allocation format alone is insufficient. Keep the sampler comparison/filter/address traits, including whether compareOp is NONE or a comparison operation, separately from ordinary sampler namespace membership. Preserve the AS descriptor's creation provenance and owning scene/build lifetime. Color/depth/shading-rate attachment views and SUBPASS_INPUT remain their declared attachment interfaces and are not resource-heap registrations.

Index(handle, expectedClass) first validates registry/epoch, generation, live publication state and namespace, then the exact class. Validate the expected texture shape, typed format interpretation, structured stride and access intent against retained traits before publishing the GPU record. Re-registering a different class creates a new handle/record version through the usual fresh-slot and retirement protocol. Class admission is backend-specific: a typed view class that lacks the selected transport's capability evidence remains rejected even when its CPU handle is otherwise valid.

The current SDK exposes GetBufferDesc and GetTextureDesc for underlying allocations, descriptor factories, and GetDescriptorNativeObject. It exposes no public GetDescriptorType/GetDescriptorViewDesc query. Native-object inspection and casts to Source/Validation classes are outside this consumer contract. Creation traits therefore establish trusted factory provenance, not independent inspection of an arbitrary opaque Descriptor pointer. External/unknown descriptors need an ownership adapter that supplies verified creation provenance before registration; unknown classes are rejected. A future optional inspection interface would need the full exact view traits to independently validate raw-versus-structured, shape and format, rather than only a coarse DescriptorType. Such an interface is a separate public-API/SDK qualification change.

### Initial color Texture2D and regular sampler profile

The first trusted MIRA texture profile admits exact RGBA8_UNORM source/view formats, TextureView::TEXTURE or STORAGE_TEXTURE, a TEXTURE_2D allocation with depth/layer/sample count one, identity component mapping and a color plane. Source and view formats match exactly. The public API has no general view-format-family compatibility query; equal block sizes, channel counts, or separate GetFormatSupport results do not establish reinterpretation compatibility. Expanding to sRGB, other float formats, compression, planes, arrays, cubes or multisampling requires an explicit profile and its native operation evidence.

Validate each offset before subtracting a REMAINING count. Resolve the remaining mip range against TextureDesc::mipNum; in the ordinary nonarray 2D profile, layer/slice offsets are zero and effective counts are one. Require every normalized count to be nonzero and in range. Sampled SRVs can describe their admitted mip range, while a storage Texture2D view exposes exactly one mip: reject a remaining multi-mip range rather than recording multiple mips that the D3D12 UAV does not expose. Preserve effective view-relative extents for shader-record bounds.

Normalize PlaneBits::ALL to COLOR in this single-color-plane profile. An UNDEFINED declared view layout resolves to SHADER_RESOURCE or SHADER_RESOURCE_STORAGE according to the view type; GENERAL is an explicitly admitted alternative. Retain the resolved layout in factory traits and expected-view matching. That declaration performs no resource transition. MIRA's initial simultaneous-sharing profile additionally requires GENERAL; keep that host policy distinct from native resource synchronization and queue ownership.

FormatProps::isSrgb is distinct from isNorm/isFloat in the current SDK: RGBA8_SRGB has isSrgb set without either of the latter flags. Conversely, NV12_UNORM, P010_UNORM and P016_UNORM have isNorm set but are planar video formats. A broad float-or-normalized predicate is not a color Texture2D admission policy. On D3D12, the FormatSupportBits::TEXTURE result aggregates native shader sampling or shader load support; STORAGE_TEXTURE reports typed UAV-view support. Neither result proves every filter, typed load/store or atomic operation. Preserve the separate format/operation qualification gate when widening the initial profile.

The initial trusted regular sampler profile matches the native fixture: normalized coordinates, NEAREST min/mag/mip filtering, AVERAGE reduction, zero bias and LOD limits, no comparison or integer-border interpretation, and CLAMP_TO_EDGE/REPEAT addressing. MIRA explicitly normalizes anisotropy zero to one and retains/passes the same effective SamplerDesc through factory and expected-state validation. Check enum ranges, finite float fields, ordered LOD bounds and queried bias/anisotropy limits before the native factory, then retain the exact admitted sampler state. Linear/anisotropic filtering, reduction filtering, sRGB/other format pairs, comparison and border sampling remain distinct profile/evidence extensions; a global reduction feature alone does not qualify every format/filter pair. Sampler creation and texture/sampler operation pairing remain separate gates.

### Durable per-class capability and fallback admission

Persist three independent results for each registration/shader accessor: admitted descriptor transport and capacities, successful public factory provenance with exact view traits, and support/qualification for the actual shader operation. Native heap availability proves neither a view format nor an atomic/filter/ray operation. The native factory result and OpenRHI/native validation remain mandatory evidence alongside host class guards.

| Descriptor/accessor class | Public admission evidence in addition to transport |
|---|---|
| Sampled texture | Resource SHADER_RESOURCE usage, GetFormatSupport(viewFormat) contains TEXTURE, exact dimension/array/cube/MS shape and subresource range, matching scalar interpretation; admit sampling/filtering operations as a qualified texture/sampler pair |
| Storage texture | Resource SHADER_RESOURCE_STORAGE usage, STORAGE_TEXTURE format support and matching writable shape/range. Atomics additionally require STORAGE_TEXTURE_ATOMICS and the corresponding shader operation/type support. Unknown-format reads/writes require both the format STORAGE_READ_WITHOUT_FORMAT/STORAGE_WRITE_WITHOUT_FORMAT support and matching shaderFeatures fields |
| Typed buffer SRV / UAV | BUFFER / STORAGE_BUFFER view-format support, correct resource read/write usage, offset/size/alignment and typed scalar interpretation; typed UAV atomics additionally require STORAGE_BUFFER_ATOMICS and shader operation/type support |
| Structured / raw buffer SRV / UAV | Exact BufferView, read/write usage, normalized byte range and memoryAlignment.bufferShaderResourceOffset; structured access retains the effective view stride, raw access retains its byte-address interpretation. Validate the shader record's element layout and bounds |
| CBV | CONSTANT_BUFFER usage, memoryAlignment.constantBufferOffset and memory.constantBufferMaxRange, normalized byte range and reflected shader constant layout |
| Sampler | Separate sampler namespace/budget, regular-versus-comparison operation, configured filter/address/anisotropy and LOD bounds. Use features.filterOpMinMax for MIN/MAX filtering, shaderFeatures.unnormalizedCoordinates when requested, and other.samplerAnisotropyMax/samplerLodBiasMax. Qualify the actual sampled format/operation pair |
| AS | RayTracingInterface availability and the pass's ray-tracing tier: tiers.rayTracing>=1 for basic AS/ray-tracing pipeline use, >=2 for the declared public ray-query path. Retain completed build/update barriers, AS lifetime and matching shader entry/payload metadata |

For the currently admitted D3D12 structured-buffer factory, require a nonzero four-byte-multiple effective stride no greater than 2,048 bytes, the pinned Agility SDK 1.619.6 D3D12_REQ_MULTI_ELEMENT_STRUCTURE_SIZE_IN_BYTES limit. Normalize WHOLE_SIZE only after checking offset against the allocation size; use subtraction-based bounds, require view offset/size to contain whole elements, apply memoryAlignment.bufferShaderResourceOffset, and bound view bytes by the queried memory.storageBufferMaxRange. That public range is a byte limit, not an element count; the native NumElements calculation is viewBytes/stride. The current uint32_t byte-range cap together with a stride of at least four keeps that count within the native uint32_t field. A large allocation may supply a smaller admitted view. Schema/element-layout matching and underlying resource usage remain additional checks. Successful factory creation is required before registration; native validation is not a replacement for rejecting an unsupported host class/stride request.

The current public SDK supplies no buffer-to-device introspection and cannot prove that an arbitrary shared ownership token controls that buffer. A same-device buffer and an ownership token that actually keeps that allocation alive are trusted caller preconditions of the module/host factory contract. Registry identity validates handles, not the provenance of an arbitrary opaque resource pointer. Preserve that explicit boundary rather than inspecting native/private objects or adding inferred device-ownership checks.

Resolve WHOLE_SIZE and REMAINING traits against the owning BufferDesc/TextureDesc before publishing bounded records. Preserve texture slice, plane, component-mapping and declared view-layout traits as well as mip/layer/shape/format; the view's declared access-time layout is not a tracked resource transition. Root descriptors/constants and shader-buffer address transports have their own alignment, range, layout and operation gates even when a resource is also heap-registered.

For Vulkan indexed arrays, nonuniform capability admission is per descriptor class: sampled textures and samplers use shaderSampledImageArrayNonUniformIndexing; CBV arrays use shaderUniformBufferArrayNonUniformIndexing; structured/raw SRV and UAV arrays use shaderStorageBufferArrayNonUniformIndexing; typed buffer SRVs/UAVs use shaderUniformTexelBufferArrayNonUniformIndexing / shaderStorageTexelBufferArrayNonUniformIndexing; storage textures use shaderStorageImageArrayNonUniformIndexing. These are distinct [Vulkan feature flags](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceVulkan12Features.html). The current public DeviceCapabilityBits reports only sampled-image nonuniform indexing among those per-type flags. Reject unknown classes for this array transport until OpenRHI supplies explicit public evidence and the pinned shader/native qualification passes. A broad bindless tier, Vulkan version, shader model, successful resource creation or sampled-image feature does not admit the other classes. Update-after-bind support and limits are additionally per type when that behavior is requested. Native EXT heap and device-address transports are separately admitted paths; changing transport requires matching shader/reflection and native evidence.

A trusted AS descriptor factory retains the actual same-device TLAS owner, its backing allocation lifetime and its known AccelerationStructureDesc type/flags/capacity from the AS-creation adapter. Pair a stable scene/schema identity with the built/update version, completion/barrier state and descriptor/record epoch. RayTracingInterface supplies CreateAccelerationStructureDescriptor, GetAccelerationStructureHandle and GetAccelerationStructureBuffer, but no AS GetDesc or resource-to-device introspection. Those getters supply opaque handles/backing references, not independent TLAS/type/device attestation. For ray-query registration require known TOP_LEVEL provenance and tiers.rayTracing>=2, together with the public interface and admitted heap transport. Replacing, compacting or relocating the AS creates a fresh descriptor/record version and retires every old borrower; in-place updates also require explicit ordering against every reader. Build/AS memory barriers and completion publication remain separate from descriptor creation and host ownership retention.

Host callbacks report a structured class/feature/limit rejection and keep requested settings separate from active execution. A caller may select another qualified transport with the same declared shader semantics; it must not silently substitute fixed per-object binding or weaken a typed access. OpenRHI owns any future feature-query or descriptor-inspection extension and its backend/Validation/compiler/SDK qualification. Module callbacks consume the published public contract and retained creation traits.

Native migration tests pair factory creation with the recorded class/traits and exercise wrong-class, raw-versus-structured, SRV-versus-UAV, texture-shape, typed-format and comparison-sampler rejection. Retain the module callback schema/version with the shader-record schema. Heap writes continue to use the existing public descriptors and indices; this class vocabulary adds no OpenRHI ABI or native backend dependency to module callbacks.

## Registry publication, release and reuse

MIRA's CPU handle contains `{registryId,index,generation,kind}`. Resource and sampler handles use separate types/namespaces; registry identity includes the device/heap epoch. Zero or another reserved sentinel is never dereferenced. Reserve and populate appropriate typed defaults (such as white/normal material textures) and default samplers before publishing records. Missing materials choose a valid declared default handle; invalid handles fail host validation. Do not assume a null/unwritten descriptor returns a defined value.

Allocate from a bounded free list, initialize the native descriptor, then publish the validated typed index into a GPU record. On update, allocate a fresh slot and publish a new record version; preserve the old slot, resource, view and record version while any recorded or submitted work can reference them. A CPU descriptor update is neither a resource transition nor proof that the GPU has stopped reading the old slot.

Release immediately invalidates the CPU handle for new publications and moves its slot to retirement. Withdraw or repoint every persistent GPU scene/material/geometry record version that contains the old numeric index before releasing its publication lease; old indices in published records can otherwise be read by future frames. Stop new recording leases and retain leases for already recorded but unsubmitted command buffers. After submission, attach the final last-use completion fence; cancellation releases its recording lease explicitly. Collect only when every relevant queue use and recording lease has retired. MIRA currently uses one shared graphics queue; future independent queues must converge onto an explicit retirement fence or track a vector of queue completions before collection. Numeric values from unrelated fences are incomparable.

After collection, release the registry retention and notify the owning module that its view/resource borrower has retired; the native object owner releases objects after all borrowers finish. Increment the generation and return the slot to the free list. Quarantine a slot on generation wrap; a stale handle must never become valid again within the registry lifetime. Replacing/growing a heap creates a new registry/heap epoch, migrates live records/descriptors, and retires the old heap after all borrowers finish. Exhaustion returns a concrete allocation failure with used/free/retiring counts. It never silently overwrites a live descriptor.

## UI, AMD and conventional-pass coexistence

The shared heap persists across module passes. UI and vendor adapters retain their supported public interfaces and native resource contracts. A conventional pass may bind its own pool/layout and replace the currently bound native heaps. On returning to a bindless module pass, bind the shared heap first, then that pass's pipeline layout, pipeline and root payload. Conversely, establish all required conventional state before a UI/vendor pass. Resource-state transitions, FSR/FG COMMON handoffs and fences remain explicit. MIRA's FG/VSync requested defaults are independent of heap availability and remain application-owned.

## Qualification and migration gates

1. Record interface/capabilities, capacities, adapter/OS/driver/backend and the chosen transport; reject unsupported classes before pipeline creation or record publication.
2. Match pinned shader binary/reflection to root schema, nonuniform operations, resource kinds and sampler indices. Preserve all native layouts and threadgroup metadata.
3. Native readback must prove GPU-selected noncontiguous resource slots with zero per-object descriptor-set binding. Exercise sampled texture plus separate sampler, SRV/UAV structured/raw/typed buffers and AS where the pass uses them.
4. Qualify host generation/type/registry rejection, exhaustion, update-to-fresh-slot, recorded/unsubmitted borrowers, multi-frame retirement, stale-handle reuse and heap-epoch change. Use the MIRA registry's tests for these host responsibilities.
5. Run mixed UVRT/FACET -> ImGui -> AMD -> module sequences with explicit state rebind and native validation. Exercise moving objects/materials, streaming and camera changes; inspect actual scene records and dispatches rather than counting renamed set bindings.
6. Maintain a pass inventory covering scene geometry/materials, UVRT lighting, shadows/environment, temporal guides, resolve/composition, debug/UI and post-processing. Classify UI/vendor internal transports by their owning public interface and qualify the caller transition. Preserve correct lighting ownership while migrating descriptor transport.
7. Publish native per-backend receipts before admitting that transport in production. Correctness and measured performance remain separate gates.
