# AMD frame generation and presentation

OpenRHI's `FrameGenerationInterface` owns the pinned AMD FSR SDK 2.3.0 D3D12 frame-generation context and proxy swapchain. The public C/C++ facade is `Include/Extensions/OpenRHIFrameGeneration.h`. Maintained Windows x64 D3D12 builds enable `OPENRHI_ENABLE_FFX_SDK`, `OPENRHI_ENABLE_ANTILAG2_SDK`, and `OPENRHI_ENABLE_FFX_FRAME_GENERATION` by default. Applications rebuild against the matching headers and SDK.

## Creation and ownership

Enumerate eligible providers on the actual device, then create a context with a graphics queue, HWND, display size, maximum render size, swapchain format, depth/motion flags and transfer function. Provider id zero selects AMD's default; an enumerated id requests that provider explicitly. Creation and the queried interface are distinct eligibility gates. The pinned public APIs are FG 4.0.1 and D3D12 proxy 3.1.7.

Retire game-queue and presentation work and destroy the previous swapchain before creating the proxy for that HWND. The context owns its effect, proxy, pacing queues/threads and wrapped backbuffer textures. `GetFrameGenerationTextures` returns borrowed OpenRHI textures valid until context destruction. The device, graphics queue and HWND outlive the context. Scene, depth, motion and UI resources remain caller owned. Externally synchronize calls on a context.

## Per-frame protocol

1. Call Anti-Lag `UpdateAntiLag` immediately before input polling. Acquire a proxy texture with `AcquireFrameGenerationTexture`.
2. Produce the scene/upscaled HUDless image and transparent UI separately. Configure generation with a nonzero frame id increasing by exactly one, optional HUDless color and optional UI resource. UI uses RGBA8_UNORM or RGBA16_SFLOAT. Set `uiPremultiplied` to match its actual pixels. Enabled configuration must precede preparation for that frame.
3. Transition every D3D12 FSR SR input, guide and output to `{AccessBits::COMMON, Layout::GENERAL, StageBits::ALL}` before `CmdDispatchUpscale`. The adapter supplies typed public formats and native COMMON state to AMD and returns the resources in that state. This handoff also applies to FG depth/motion before and after preparation and HUDless/UI through Present plus Wait. `NONE` describes no access and is distinct from this common handoff. [Microsoft's Enhanced Barrier interop contract](https://microsoft.github.io/DirectX-Specs/d3d/D3D12EnhancedBarriers.html#interop-with-legacy-resourcebarrier) requires native COMMON between legacy and enhanced barriers.
4. Record `CmdPrepareFrameGeneration` outside rendering with R32_SFLOAT hardware depth values, RG16_SFLOAT or RG32_SFLOAT motion, jitter, render dimensions, camera basis and frame time. Motion scale converts stored vectors to pixels: use (1,1) for pixel motion or render dimensions for UV motion. Depth and render-resolution motion allocations may cover the active top-left render region through the context maximum render dimensions; HUDless/UI and display-resolution motion match display size exactly. Supply physical near/far planes; the adapter applies infinite far (`FLT_MAX`) and reversed-depth swapping, matching `UpscalerInterface`. Far is ignored when `DEPTH_INFINITE` is set. Reset on discontinuities.
5. Copy the HUDless scene into the acquired proxy texture using explicit caller barriers, then return the proxy texture to `{NONE,PRESENT,NONE}`. Register the UI separately; the SDK composites it onto rendered and generated output. `DrawImguiDesc::writeAlpha=true` writes premultiplied RGB and alpha into a transparent attachment; encoded SDR scene/UI use `linearColor=false` and an UNORM attachment, with SRGB FG transfer.
6. Submit the game queue, mark Anti-Lag render end, set rendered frame type and call `PresentFrameGeneration(context,syncInterval)`. Zero permits tearing when requested and supported; one enables VSync. The SDK records interpolation during Present and owns pacing. Its callback dispatch failure is returned even when DXGI Present succeeds.
7. `WaitFrameGeneration` drains provider presentation work. Also retire game-queue GPU work before resource reuse/release. This explicit serial protocol establishes correctness; callers may pipeline only while preserving every resource lifetime.

Disable with an empty configure descriptor, wait for provider presents, and retire caller work before resizing/releasing borrowed resources. Detach the Anti-Lag swapchain reference before destroying the proxy. Recreate on display/format/max-render-size changes. A new enabled frame requires fresh preparation; duplicate preparation and repeated enabled Present are rejected.

## Deployment and qualification

Deploy the matching OpenRHI DLL/import library, Agility SDK 1.619.6, AMD loader, upscaler, framegeneration, denoiser and radiancecache DLLs from the qualified SDK. Preserve original `ThirdPartyLicenses/fsr/LICENSE.md`, `ThirdPartyLicenses/fsr/3rdpartynotice.md`, and the Anti-Lag 2 license. Vendor headers and binaries remain unmodified at FSR commit `60f4ea81909200d8542eca14dccb2628b763a9a3` and Anti-Lag commit `390aa4a8c8655d0ae6e90079db2c85e103a96da3`.

`OpenRHI.AMD.FrameGeneration` runs actual FSR 4.1.1 SR readback, Anti-Lag update/markers/private-data attachment, FG 4.0.1 preparation/interpolation and DXGI presentation on the Radeon RX 9070 XT, with native validation and OpenRHI Validation on/off. Its enabled block records eight prepared game frames, eight generated dispatches/frames and sixteen DXGI presents per mode with zero unexpected validation errors; it also checks disable/resume, VSync, waitable acquisition/tearing, a 320x180 active guide region inside persistent 640x360 allocations, and seven rejected public contracts. The transparent ImGui alpha path has native pixel readback in `OpenRHI.D3D12.UI`.

Keep interface availability, provider enumeration, context creation, prepared/submitted frames, successful generation dispatches, generated frames recorded and actual DXGI present count distinct. These counters establish execution, while motion quality, pacing distributions and measured input-to-display latency require application workloads and separate receipts. Windows x64 Debug and Release each pass 21/21 tests; the AMD/UI-disabled NONE build passes ten tests with adapter selection skipped. Apple/Vulkan runtime, HDR output, other adapters and measured latency remain separate native qualification gates. Logs, native identity and SDK hashes are retained under `_Tmp/AMD/`.
